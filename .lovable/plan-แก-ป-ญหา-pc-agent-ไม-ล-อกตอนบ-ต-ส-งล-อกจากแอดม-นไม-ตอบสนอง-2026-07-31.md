# แก้ปัญหา PC Agent: ไม่ล็อกตอนบูต + สั่งล็อกจากแอดมินไม่ตอบสนอง

## สาเหตุที่พบจากการตรวจโค้ด

1. **คำสั่งจากแอดมินน่าจะอ่านไม่ได้เลย (จุดต้องสงสัยหลัก)**
   `GetPendingCommandsAsync()` กรองคำสั่งค้างด้วย `Filter<string>("ack_at", Operator.Is, null)` ซึ่งใน Supabase.Postgrest 4.x มักสร้าง query ผิดรูปและได้ error กลับมา ตัวเรียกใช้ใน `App.xaml.cs` ครอบด้วย `try { ... } catch { return; }` → ถ้าพัง จะเงียบสนิท ไม่มีอะไรเกิดขึ้นบนเครื่องลูก ตรงกับอาการ "กดล็อกแล้วไม่มีการตอบสนอง" ทุกประการ (ทั้ง realtime และ polling เรียกฟังก์ชันเดียวกันนี้)
   *ยังไม่ยืนยัน 100% เพราะรันบนเครื่อง Windows จริงไม่ได้จากที่นี่ — จึงต้องมี log เพื่อยืนยัน (ข้อ 2)*

2. **ไม่มี log เลย** ทุก error ถูกกลืนด้วย `catch { }` ว่าง จึงบอกไม่ได้ว่าเอเจนต์รันอยู่ไหม เชื่อมต่อสำเร็จไหม หรือ query พัง — ต้องแก้ก่อนเป็นอันดับแรก

3. **ตอนบูตแล้วไม่ล็อก** มีได้ 2 ทาง
   - เอเจนต์ไม่ได้เริ่มทำงาน (Scheduled Task `AtLogOn` + Run key อาจถูกบล็อก/ไฟล์ถูกทับตอนอัปเดต) หรือ
   - เอเจนต์เริ่มแล้ว init ล้มเหลว (ตอนบูตเน็ตยังไม่พร้อม) → โค้ดปัจจุบัน `Shutdown(1)` ทิ้งภายใน 10 วินาที หน้าล็อกจึงหายไป และรอ watchdog อีกไม่เกิน 2 นาที = ช่วงนั้นลูกค้าเห็นเดสก์ท็อป
   - ไม่มี single-instance guard → ถ้า Run key + Scheduled Task เปิดพร้อมกันจะได้ 2 โปรเซส แย่งหน้าจอกัน

## แผนแก้ไข

**A. ใส่ระบบ log (ทำก่อน เพื่อวินิจฉัยได้จริง)**
- เขียน log ลง `C:\YALA\agent.log` (หมุนไฟล์เมื่อเกิน ~1 MB): เวลาเริ่มโปรแกรม, เวอร์ชัน, MachineId, ผล init, subscribe สำเร็จ/ล้มเหลว, จำนวนคำสั่งค้างที่ดึงได้, คำสั่งที่ประมวลผล, ack สำเร็จ, และ exception เต็มรูปแบบ
- แทนที่ `catch { }` ว่างทั้งหมดด้วยการ log

**B. แก้ query คำสั่งค้าง**
- เปลี่ยนไปใช้รูปแบบที่ SDK รองรับแน่นอน (`.Where(x => x.AckAt == null)` หรือ filter แบบ `is.null` ที่ถูกต้อง)
- ถ้ายังพลาด ให้ fallback: ดึงคำสั่ง 20 รายการล่าสุดของเครื่องนี้แล้วกรอง `AckAt == null` ในหน่วยความจำ (กันพังแบบเงียบอีก)

**C. ทำให้เอเจนต์ไม่ตายและล็อกตั้งแต่บูต**
- ใส่ single-instance mutex (โปรเซสที่สองปิดตัวเอง)
- ตอน init ล้มเหลว ไม่ต้อง `Shutdown` — คงหน้าล็อกไว้แล้ววน retry ทุก 10 วินาทีจนสำเร็จ (เครื่องลูกจะถูกล็อกเสมอแม้เน็ตยังไม่มา)
- แสดงสถานะบนหน้าล็อกให้เห็นชัด: เวอร์ชันเอเจนต์ + "เชื่อมต่อแล้ว/กำลังลองใหม่" + เวลาที่ sync ล่าสุด เพื่อดูด้วยตาว่าเครื่องรับคำสั่งได้หรือไม่

**D. ปรับตัวติดตั้ง (`install.ps1`)**
- เพิ่ม trigger `AtStartup` (delay ~30 วินาที) ควบคู่ `AtLogOn`, เพิ่ม `-RestartOnIdle`/`StartWhenAvailable` ให้ครบ
- ลดช่วง watchdog เหลือ 1 นาที
- ท้ายสคริปต์พิมพ์รายงานตรวจสอบ: เวอร์ชันไฟล์ exe ที่ติดตั้ง, ค่า registry ทั้งหมด, สถานะ task ทั้ง 2 ตัว, และโปรเซสที่รันอยู่ — จะได้รู้ทันทีว่าติดตั้งครบไหม
- เพิ่มโหมด `-Diagnose` สำหรับรันตรวจอย่างเดียว และแสดง 30 บรรทัดท้ายของ `agent.log`

**E. ฝั่งเว็บแอดมิน (`PcZonePanel.tsx`)**
- แสดงเวอร์ชันเอเจนต์ + "heartbeat ล่าสุดเมื่อ X วินาทีที่แล้ว" ต่อเครื่อง เพื่อแยกให้ออกว่า "เอเจนต์ไม่รัน" กับ "เอเจนต์รันแต่ไม่รับคำสั่ง"
- เตือนสีแดงในประวัติคำสั่ง เมื่อคำสั่งค้างไม่ถูก ack เกิน 30 วินาที

## ขั้นตอนทดสอบหลังแก้

1. Build `YalaPcAgent.exe` ใหม่ให้ผ่าน แล้วรัน `install.ps1` ทับบนเครื่องลูก (สคริปต์รองรับอัปเดตทับ)
2. บนหน้าแอดมินต้องเห็น heartbeat เดินและเวอร์ชันใหม่ (2.2.0)
3. กด "ล็อกเครื่อง" → เครื่องลูกล็อกภายในไม่กี่วินาที และประวัติขึ้น "ตอบรับแล้ว"
4. รีบูตเครื่อง → ต้องเห็นหน้าล็อก YALA ทันทีหลังเข้า Windows (auto-login เปิดไว้แล้ว)
5. ถ้ายังไม่ทำงาน ส่ง `C:\YALA\agent.log` มาให้ดู จะระบุสาเหตุได้ทันที
