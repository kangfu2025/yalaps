# เอกสารวิเคราะห์ PC Agent v2.5.0 (ก่อนติดตั้งจริง) สำหรับส่งให้ Claude

## สถานะที่ตรวจสอบจากโค้ดจริงในโปรเจกต์

- โค้ดถูกแก้เป็นเวอร์ชัน 2.5.0 แล้ว: `SupabaseService.cs:17` = `AgentVersion = "2.5.0"`
- `CountdownOverlay.xaml` ปัจจุบัน `AllowsTransparency="False"`, ขนาดคงที่ 250x96, `ShowActivated="False"`
- `CountdownOverlay.xaml.cs` มีตัวจับ fullscreen (`_fsTimer` ทุก 2 วินาที) เรียก `WinLock.IsFullscreenAppActive()` เพื่อ Hide/Show overlay
- `App.xaml.cs:329` มีตัวกัน "ไม่มี session" 1 รอบ (`_noSessionStreak < 2`) และ `ShowLock` ไม่ Activate ซ้ำเมื่อหน้าล็อกแสดงอยู่แล้ว
- ยังไม่มีโฟลเดอร์ build `bin/Release/net8.0-windows/win-x64/publish` ในโปรเจกต์ตอนนี้ (ไฟล์แจกใน `/mnt/documents` ที่มีคือชุด 2.4.0)
- เครื่องลูกยังไม่ได้ติดตั้ง 2.5.0 และยังไม่มีไฟล์ `.log` เพราะ `Log.cs` เขียนที่ `AppContext.BaseDirectory\agent.log` (คือ `C:\YALA\agent.log`) และจะ fallback ไป `%ProgramData%\YALA\agent.log` เมื่อเขียนไม่ได้ — ไม่มีการเขียน log แยกรายวันตามที่เคยเข้าใจ

## สิ่งที่จะส่งมอบ

เอกสาร Markdown ฉบับใหม่ `pc-agent-analysis-2.5.0.md` (ภาษาไทย + ศัพท์เทคนิคอังกฤษ) เพื่อให้ Claude วิเคราะห์แบบ static review ก่อนติดตั้ง ประกอบด้วย

1. **บริบทสำคัญที่ Claude ต้องรู้ก่อน** — v2.5.0 แก้ในโค้ดแล้วแต่ **ยังไม่ได้ติดตั้งบนเครื่องจริง**, เครื่องจริงยังรัน build เก่า, **ยังไม่มี log ใด ๆ** จึงขอให้วิเคราะห์จากโค้ดเท่านั้น ไม่ต้องขอ log
2. **สถาปัตยกรรมและ lifecycle** — startup → lock ทันที → connect/retry → heartbeat 15s / sync 30s / command poll 10s → overlay นับถอยหลัง → คำสั่ง lock/unlock/warn/shutdown/end_session + ack
3. **อาการบั๊กที่รายงาน** — เกม fullscreen เด้งออกบ่อยระหว่างเล่น (พบบน build 2.4.0)
4. **สาเหตุที่วิเคราะห์ไว้ + สิ่งที่ 2.5.0 แก้** — ตารางเทียบ 2.4.0 vs 2.5.0 (transparency/layered window, SizeToContent, Activate() ซ้ำ, Hide vs Close หน้าล็อก)
5. **จุดเสี่ยงที่ยังคาใจ ให้ Claude ตรวจเป็นข้อ ๆ**
   - `IsFullscreenAppActive()` อาศัย `SHQueryUserNotificationState` + เทียบขนาดกับ `GetSystemMetrics(SM_CXSCREEN)` → borderless fullscreen บนจอหลายจอ/DPI scaling อาจตรวจไม่เจอ
   - `Show()/Hide()` สลับทุก 2 วินาที อาจสร้าง z-order churn เอง
   - `Warn()` เรียก `Show(); Topmost = true;` ระหว่างเกม fullscreen → recomposite 1 ครั้งต่อการเตือน (ยอมรับได้หรือไม่)
   - `SetTimeText` ข้ามการอัปเดตขณะซ่อน แต่ `_timer` ยัง tick ทุกวินาที
   - `ShowLock()` ยัง `Activate()` ในกรณีสร้างหน้าล็อกใหม่ — ถ้า sync พลาด 2 รอบติดระหว่างเกม จะแย่งโฟกัส
   - `OnTimeExpired` ล็อกทันทีตามที่ต้องการ (ไม่ใช่บั๊ก) ระบุให้ Claude ไม่แก้จุดนี้
6. **โค้ดที่เกี่ยวข้องแบบเต็ม** — แนบ `CountdownOverlay.xaml`, `CountdownOverlay.xaml.cs`, `WinLock.cs`, ส่วน sync/ShowLock/ShowCountdown ของ `App.xaml.cs`, `Log.cs` เพื่อให้ Claude อ่านได้จบในไฟล์เดียว
7. **คำถามที่อยากให้ Claude ตอบ** — ยืนยัน/แย้งสาเหตุ, ชี้จุดที่จะยังเด้งอยู่, แนะวิธีตรวจ fullscreen ที่แม่นกว่า (เช่นเทียบ monitor rect ต่อ `MonitorFromWindow` + per-monitor DPI), และแนะว่าควรเปลี่ยน overlay ไปใช้แนวทางอื่นไหม
8. **หมายเหตุการหา log หลังติดตั้ง** — path ที่ถูกต้องคือ `C:\YALA\agent.log` หรือ `C:\ProgramData\YALA\agent.log`
