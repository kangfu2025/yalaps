# ตรวจสอบโซน PC ก่อนติดตั้งจริง — ผลตรวจ + แผนแก้ไข

ตรวจโค้ดฝั่ง Agent (`pc-agent/YalaPcAgent/`), ตัวติดตั้ง (`install.ps1`), ตารางฐานข้อมูล และแผงควบคุมฝั่งแอดมินแล้ว พบปัญหาสำคัญที่ทำให้ "ควบคุมพีซีจากระยะไกล" ยังใช้งานจริงไม่ได้

## สิ่งที่ตรวจพบ

1. **Agent ไม่อ่านคำสั่งจากแอดมินเลย (บั๊กหลัก)**
   ฝั่งเว็บกดปุ่ม ล็อก / ปลดล็อก / เตือน / ปิดเครื่อง แล้วบันทึกลงตาราง `pc_commands` สำเร็จ (เห็นแถวคำสั่งจริงในระบบ) แต่ตัว Agent สมัครรับข้อมูลเฉพาะตาราง `pc_sessions` เท่านั้น ไม่มีโค้ดใดอ่านหรือประมวลผล `pc_commands` → คำสั่งทุกคำสั่งค้างอยู่เฉย ๆ ไม่มีอะไรเกิดขึ้นบนเครื่องลูก และช่อง `ack_at` เป็น null ตลอด

2. **เวลา heartbeat ถูกบันทึกเป็นปี พ.ศ.**
   ข้อมูลจริงในตาราง `pc_agents` คือ `last_heartbeat = 2569-07-24` (ควรเป็น 2026) เพราะ Agent ทำงานบน Windows ที่ตั้งค่าภาษาไทย แล้วแปลงวันเป็นข้อความตามปฏิทินพุทธ ทำให้สถานะ ออนไลน์/ออฟไลน์ บนหน้าแอดมินเชื่อถือไม่ได้

3. **เครื่องที่ 2 ยังไม่เคยส่ง heartbeat**
   มีเพียงเครื่อง PC 1 ที่เคยรายงานตัว ส่วน PC 2 ไม่มีแถวใน `pc_agents` เลย — เป็นเรื่องปกติถ้ายังไม่ได้ติดตั้ง แต่ต้องยืนยันตอนติดตั้งจริง

4. **ตัวติดตั้ง (install.ps1) ใช้งานได้** — ขอสิทธิ์ Administrator เอง, เขียน Registry, สร้าง Scheduled Task + Run key + watchdog, เริ่มโปรแกรมทันที ไม่พบข้อผิดพลาด (ข้อจำกัดเดิมยังอยู่: ต้องเปิด auto-login เพื่อให้หน้าล็อกขึ้นทันทีหลังบูต)

5. **สิทธิ์ฐานข้อมูล/Realtime ครบ** — ทั้ง 3 ตาราง PC มี GRANT, RLS และอยู่ใน publication realtime แล้ว

## แผนแก้ไข

**A. ทำให้ Agent รับคำสั่งจากแอดมินได้จริง**
- เพิ่มโมเดล `PcCommandRow` (ตาราง `pc_commands`)
- Agent สมัครรับ realtime บน `pc_commands` เฉพาะ `machine_id` ของตัวเอง + วนตรวจคำสั่งค้าง (`ack_at is null`) ทุก 10 วินาที เผื่อ realtime หลุด
- ประมวลผลคำสั่ง:
  - `lock` → แสดงหน้าล็อก YALA ทันที (พร้อมข้อความ "ถูกล็อกโดยผู้ดูแล")
  - `unlock` → ซ่อนหน้าล็อกชั่วคราวให้แอดมินเข้าไปดูแลเครื่อง
  - `warn` → แจ้งเตือนเหลือเวลาอีกกี่นาทีบนหน้าจอลูกค้า
  - `shutdown` → ปิดเครื่อง
  - `end_session` / `show_countdown` → sync สถานะจากเซิร์ฟเวอร์ใหม่
- เมื่อทำเสร็จ ตั้ง `ack_at = now()` เพื่อให้หน้าแอดมินเห็นว่าคำสั่งถูกตอบรับแล้ว
- ข้ามคำสั่งเก่าค้างท่อ (เกิน ~10 นาที) ตอนเปิดเครื่อง เพื่อไม่ให้ shutdown เก่าย้อนมาสั่งปิดเครื่องตอนบูต

**B. แก้ปี พ.ศ. / เวลาเพี้ยน**
- บังคับ culture เป็น InvariantCulture ตอนเริ่มโปรแกรม เพื่อให้เวลาที่ส่งขึ้นเซิร์ฟเวอร์เป็นปฏิทินสากล (ค.ศ.) เสมอ

**C. ฝั่งเว็บแอดมิน**
- แสดงสถานะคำสั่งในประวัติ: "ตอบรับแล้ว" (มี `ack_at`) หรือ "รอเครื่องตอบรับ" พร้อมเวลา เพื่อให้ตรวจสอบได้ทันทีว่าเครื่องรับคำสั่งหรือไม่
- (แถวเวลา heartbeat ที่ผิดจะหายไปเองหลังติดตั้ง Agent เวอร์ชันใหม่)

**D. ตรวจสอบผลลัพธ์**
- Build โปรเจกต์ .NET ให้ผ่าน และ build เว็บให้ผ่าน
- ให้ขั้นตอนทดสอบสั้น ๆ หลังติดตั้งบนเครื่องจริง: กดล็อก → เครื่องต้องล็อกภายในไม่กี่วินาที และประวัติต้องขึ้น "ตอบรับแล้ว"

## รายละเอียดทางเทคนิค

- ไฟล์ที่แก้: `pc-agent/YalaPcAgent/Models.cs`, `SupabaseService.cs`, `App.xaml.cs`, `CountdownOverlay.xaml.cs` (เพิ่มข้อความเตือน), `src/components/shop/PcZonePanel.tsx`
- ไม่แก้สคีมาฐานข้อมูล — ตาราง `pc_commands` มีคอลัมน์ครบแล้ว
- ต้อง build `YalaPcAgent.exe` ใหม่แล้วรัน `install.ps1` ซ้ำบนเครื่องลูก (สคริปต์รองรับการอัปเดตทับอยู่แล้ว)
